# agents_driven_sdlc

Девять скилов Codex для подготовки и реализации изменений в программном продукте. Общий CR связывает результаты ролей, правила конкретного проекта задают его `AGENTS.md` и документация.

Единая версия комплекта хранится в [VERSION](VERSION). Изменения описаны в [CHANGELOG.md](CHANGELOG.md), правила SemVer и выпуска в [RELEASE.md](RELEASE.md).

Комплект распространяется по [лицензии MIT](LICENSE). Заимствованные материалы и уведомления об авторстве перечислены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Порядок работы

UX-макет → верификация пользователем → постановка → сценарии → архитектура → проверки → план → ревью пакета → утверждение пользователем → реализация.

UX-этап применяется при изменении интерфейса, медиация возникает при аргументированном споре. После проектирования проверок архитектор дополняет карту файлов до передачи планировщику.

Общее дерево решений ведётся с UX-этапа и передаётся продакту вместе с макетом. Блокирующий продуктовый вопрос разрешается до проверки зависимого UI; дерево хранится в свободной краткой форме и отдельно не согласуется.

Эти инструкции подключаются по задаче.

## Использование

Для полного цикла передай идею, контекст и ограничения:

```text
Используй $orchestrator, чтобы подготовить пакет решения по этой идее,
показать его мне на утверждение и реализовать согласованный план: …
```

Для продолжения укажи CR, утверждённую версию и текущий этап. Для отдельного артефакта вызови соответствующий скил напрямую.

## Установка

Разбор решений и понятий входит в комплект. Для UX-показа используются доступные `visualize` и `modern-web-guidance`.

Установщик создаёт симлинки всех девяти скилов в `~/.agents/skills`, не перезаписывая обычные файлы и каталоги. Это общая установка для проектов пользователя. [Codex поддерживает симлинки скилов](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills).

### Конкретная версия

Нужны Git, Bash и локальный клон этого репозитория. Выполняй команды из его корня после создания релизного тега. Если нужного тега ещё нет локально, получи его с сервера:

```bash
git fetch origin tag v0.1.0
```

Укажи нужный тег в `release_tag`. Блок создаёт отдельный worktree или проверяет уже существующий, затем переключает пользовательские симлинки на него:

```bash
(
  set -e
  release_tag=v0.1.0
  release_dir="../agents_driven_sdlc-${release_tag}"
  release_commit="$(git rev-parse --verify "refs/tags/${release_tag}^{commit}")"
  if [[ ! -e "$release_dir" ]]; then
    git worktree add --detach "$release_dir" "$release_commit"
  fi
  test "$(git -C "$release_dir" rev-parse HEAD)" = "$release_commit"
  test -z "$(git -C "$release_dir" status --porcelain)"
  test "$(cat "$release_dir/VERSION")" = "${release_tag#v}"
  bash "$release_dir/scripts/install.sh"
  git -C "$release_dir" rev-parse HEAD
)
```

Если проверка завершилась ошибкой, установка не запускается. Сверь выбранный тег, путь, версию и локальные изменения; не удаляй их для обхода проверки. Сохрани выведенный полный SHA вместе с номером версии, если нужно воспроизвести использованный комплект.

Не редактируй установленный worktree и не удаляй его, пока симлинки указывают на него. Detached HEAD не защищает файлы от правок. После переключения начинай новую задачу; если Codex не увидел изменения, перезапусти его.

### Обновление и откат

Выполни тот же блок с тегом нужного выпуска. Для возврата к первому выпуску укажи `release_tag=v0.1.0`; при сохранённых теге и worktree сеть не нужна. Повторная установка переключит ссылки обратно, рабочая копия разработки останется на месте.

Перед откатом прочитай разделы перехода в changelog пропускаемых выпусков. Старый установщик не знает о скилах, добавленных позже; если состав менялся, удали только перечисленные там лишние симлинки комплекта. Откат скилов не отменяет уже созданные ими файлы проекта.

Для другого каталога задай `AGENTS_SKILLS_DIR` перед установкой и используй тот же каталог при обновлении и откате:

```bash
export AGENTS_SKILLS_DIR=/path/to/skills
```

Этот параметр меняет место симлинков; обнаружение нестандартного каталога в Codex настраивается отдельно.

### Рабочая копия для разработки

Чтобы установить текущие исходники без фиксации на выпуске, из корня этой рабочей копии выполни:

```bash
./scripts/install.sh
```

Симлинки будут указывать на неё, включая незакоммиченные изменения. Вернуться к выпуску можно повторной установкой по его тегу.
